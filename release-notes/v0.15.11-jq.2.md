# v0.15.11-jq.2

> fork 自有修复版本。基线 = 上游 0.15.11（未变），jq 后缀 .1 → .2。

## 二开修复

### 修复 Codex 订阅登录 403（`unsupported_country_region_territory`）

**问题**：在 Proma 里用 ChatGPT Codex 订阅登录时，token exchange 阶段报
`OpenAI Codex token exchange failed (403): unsupported_country_region_territory`，
即使设置里已开代理也无效。而 pi cli / oh-my-pi cli 正常。

**根因**：Codex OAuth 的登录（`loginCodexOAuth`）与刷新（`refreshCodexOAuth`）
直接使用原始全局 `fetch`，**绕过了 Proma 的代理设置**。Pi SDK 的 token exchange
（打 `https://auth.openai.com/oauth/token`）内部是裸 `fetch()`，没有代理注入点。
国内直连时 OpenAI 按出口 IP 做地域拦截，返回 403。

**修复**：新增 `withCodexOAuthProxy()` 包装器——
1. `installPiRequestProxyFetch()` 确保全局 fetch 已换成「读 AsyncLocalStorage dispatcher」版本；
2. 用 `getEffectiveProxyUrl()` 读取设置里的代理；
3. `createPiRequestProxyDispatcher()` + `runWithPiRequestProxy()` 让整个 OAuth 流程
   （含 token exchange / refresh）在代理异步链里执行，SDK 的裸 `fetch` 即被路由进代理；
4. 结束后关闭 dispatcher 释放连接池。

**验证**（网络层对照实验，打 `auth.openai.com/oauth/token`）：
- 强制直连 → `403 unsupported_country_region_territory`（修复前状态）
- 走代理 → 到达 OpenAI（`400 missing client_id`，业务错误，说明已连通）
- 模拟修复机制 → 同样经代理到达 OpenAI

**使用前提**：设置 → 代理 → 启用（系统代理或手动均可），代理需能访问 OpenAI。
